# جسر BLE ↔ COM لجهاز CH05 (GeoScan3D)

شريحة ESP32-S3 داخل M5Stack CoreS3 لا تملك راديو Bluetooth Classic، لذا لا يمكنها
فتح منفذ COM كلاسيكي تلقائياً كما تفعل وحدة CH05/HC-05 الحقيقية عبر SPP. هذا
السكربت يسد الفجوة على ويندوز: يتصل بالجهاز عبر BLE وينشئ طرفاً على منفذ COM
افتراضي، فيبدو الجهاز لأي برنامج (مثل Visualizer 3D) كأنه CH05 حقيقي متصل عبر
منفذ تسلسلي عادي.

## المتطلبات

- ويندوز 10/11 مع بلوتوث منخفض الطاقة (BLE) يدعمه.
- بايثون 3.9 أو أحدث.
- [com0com](https://com0com.sourceforge.net/) — أداة مجانية لإنشاء زوج منافذ COM افتراضية.

## خطوات الإعداد

1. **ثبّت com0com** وأنشئ زوج منافذ افتراضي، مثلاً `COM10 <-> COM11`
   (من أداة الإعداد الخاصة بـ com0com، `setupc.exe`، الأمر: `install PortName=COM10 PortName=COM11`).

2. **ثبّت متطلبات بايثون**:
   ```
   pip install -r requirements.txt
   ```

3. **شغّل الجهاز** (M5Stack مع فيرموير CH05) وتأكد أنه يظهر باسم `CH05` في مسح
   البلوتوث على ويندوز (لا حاجة لإقرانه يدوياً من إعدادات ويندوز — هذا السكربت
   يتصل به مباشرة عبر BLE).

4. **شغّل الجسر**، مع تخصيص أحد طرفي زوج com0com له (مثلاً COM11):
   ```
   python ble_com_bridge_win.py --com COM11
   ```
   اترك السكربت يعمل في نافذة الطرفية.

5. **افتح Visualizer 3D** ووجّهه إلى الطرف الآخر من الزوج (`COM10` في هذا المثال)،
   بنفس سرعة/تنسيق الاتصال المستخدم سابقاً مع CH05 الحقيقي — البروتوكول
   (الحزم الثنائية، أوامر THR/CAL/STEP/...) لم يتغيّر إطلاقاً، فقط طريقة نقله.

## ملاحظات

- السكربت يمرّر البايتات الخام في الاتجاهين دون تفسيرها، لذا يبقى توافقاً كاملاً
  مع أي برنامج يتحدث بروتوكول GeoScan3D الحالي عبر منفذ تسلسلي.
- إن كان للجهاز عنوان MAC ثابت وتريد تفادي البحث بالاسم في كل مرة، استخدم
  `--address AA:BB:CC:DD:EE:FF` بدل `--name`.
- إغلاق السكربت (Ctrl+C) يقطع اتصال BLE بالجهاز ويحرر منفذ COM.
